# Local Claude Code CLI inference with an allowlist of tested tools

No application API key is present, while the developer's first-party Claude Code CLI is authenticated. For this local developer-operated demo, the server runs the CLI headlessly as the agent orchestrator, after a bounded capability smoke test. Prompts go through stdin with fixed argument arrays; read only supported CLI output, never credentials or OAuth tokens. Keep requests scoped, bounded and separate from execution authority. This replaces the earlier Vercel AI SDK orchestrator: the CLI owns the tool loop, and the application's typed tools reach it through a local NextMove MCP server.

Tools are allowlist-only, and each tool has its own allowlist. [`config/agent-tools.allowlist.json`](../../config/agent-tools.allowlist.json) is the single source. Every tool starts disabled with empty `allow` lists and zero `limits`, which permit nothing; `candidates` records the values the specs mention, such as contexts, record types, merchant origins, operations, adapters and currencies. During testing a value moves into `allow` only after a test exercises it, and the entry records `enabled: true`, the verifying tests, date, commit and input-schema hash. Those tests cover every allowed value and at least one denied value. A changed schema hash means the tool is treated as disabled until re-verified. The adapter enforces this in three places: CLI flags (`--restricted`, `--strict-mcp-config` with a generated `--mcp-config`, `--tools` naming only enabled built-ins or `""`, `--allowedTools` naming only enabled tools, `--permission-prompts none` so anything else is denied), the MCP server registering only enabled tools with schemas narrowed to their allowed values, and the MCP call handler rejecting a call to a disabled tool or with any scoped argument outside that tool's `allow` lists or `limits`. User/project Claude settings must not widen the set; the smoke test confirms a non-allowlisted tool is refused.

Built-in tools that run code, write files or reach the network (Bash and other code-running tools, Write, Edit, NotebookEdit, WebFetch, WebSearch, Agent) are never allowlisted. Enabling a tool grants the model the ability to call it, not authority: mutating tools still require the server-issued approval grant from ADR 0003, and money stays with ADR 0004. An explicit API adapter may be enabled later through privately supplied configuration under the same allowlist; no secret is committed or silently sourced from unrelated projects. If live inference is unavailable, expose that fact and offer a clearly labelled deterministic simulation/manual path. A scripted fallback must never be presented as a live model decision. This developer adapter is not a public hosted authentication design or an assumption of API credits from subscriptions.
